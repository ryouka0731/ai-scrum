# 仕様書: PBI-002 （期限の設定と期限順の並べ替え）

- 対応PBI: PBI-002
- status: draft   <!-- draft（起票）→ active（スプリント確定）→ confirmed（受入済み） -->
- 作成日: 2026-08-14 / 更新日: 2026-08-14

## なぜ
締め切りが近いタスクから優先して着手できるよう、タスクに期限（日付）を設定し、期限順に並べ替えて把握したい。期限の見える化により、抜け漏れと着手順の判断ミスを防ぐ。

## スコープ（やること）
- タスク登録時・登録済みタスクへの期限（日付）設定
- 一覧への期限表示
- 一覧を期限の昇順で並べ替え
- 期限未設定タスクの判別可能な表示

## Non-goals（やらないこと）
- 降順（新しい順）並べ替えや、複数条件でのソート
- 期限超過（オーバーデュー）の強調・通知・アラート
- 時刻（時分）単位の期限管理（日付のみ扱う）
- 担当者の絞り込み（PBI-003 で扱う）
- 状態別ダッシュボード（PBI-004 で扱う）

## インターフェース / データ
- 画面:
  - 登録フォーム / タスク行に期限（日付）入力欄を追加
  - 一覧に期限列を表示（未設定は「未設定」表示）
  - 期限昇順で並べ替えるための操作（ソートボタン or ソート指定）
- API:
  - `POST /api/tasks` 入力に `due_date?: string`（`YYYY-MM-DD` / 省略可）を追加
  - `PATCH /api/tasks/:id` 入力に `due_date?: string | null`（設定・解除）を追加
  - `GET /api/tasks?sort=due_date&order=asc` → `due_date` 昇順で返却。未設定（NULL）は末尾に集約
  - 不正な `due_date` 形式は `400` `{ error: string }`
- データ構造（`tasks` テーブルへの追加列）:
  - `due_date` TEXT NULL（ISO8601 の日付 `YYYY-MM-DD`、未設定は NULL）
- 並べ替え仕様: SQL の `ORDER BY due_date IS NULL, due_date ASC`（NULL を末尾に）

## 検証方法
- 期限の異なる複数タスクを登録し、`GET /api/tasks?sort=due_date&order=asc` の順序を確認（AC-3, AC-6）。
- 画面で期限を設定・保存し、再取得で保持を確認（AC-1）、一覧表示を確認（AC-2）。
- 期限未設定タスクの「未設定」表示と並び位置を確認（AC-4, AC-6）。
- `curl` で `due_date=2026-13-40` 等の不正値を送信し 400 を確認（AC-5）。
- 並べ替えが DB クエリで行われることをコードレビューで確認（6-2）。

## 依存・リスク
- 依存: PBI-001（tasks テーブル・一覧・登録・更新の基盤）
- リスク: 日付の妥当性検証が甘いと不正値が保存される → サーバ側で `YYYY-MM-DD` 形式と実在日付を検証し、5-1 / AC-5 で担保する。
