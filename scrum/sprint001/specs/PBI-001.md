## なぜ
チームメンバーが抱えるタスクと進み具合を一箇所で登録・確認・更新できないと、抜け漏れや二重管理が起きる。登録・一覧・状態管理という中核機能を最初に成立させることで、以降の期限・担当者・ダッシュボード機能が乗る土台（SvelteKit + Node.js API + SQLite）を作る。

## スコープ（やること）
- タスクの新規登録（タイトル必須）
- タスク一覧の取得・表示
- タスク状態の変更（未着手 / 対応中 / 完了）
- SQLite への永続化（再表示・再起動後も保持）
- SvelteKit SPA + Node.js API + SQLite の初期スタック構築

## Non-goals（やらないこと）
- 期限（日付）の設定・並べ替え（PBI-002 で扱う）
- 担当者の設定・絞り込み（PBI-003 で扱う）
- 状態別ダッシュボード・集計表示（PBI-004 で扱う）
- タスクの削除・編集（タイトル変更）機能
- 認証・認可、複数ユーザーの識別
- 社内サーバへのデプロイ（order001 でスコープ外）

## インターフェース / データ
- 画面（タスク管理画面 `/`）:
  - タスク登録フォーム: タイトル入力欄（`text`、必須）＋「登録」ボタン。登録成功で入力欄をクリアし一覧を再取得。
  - 登録エラー表示: タイトル未入力で登録した場合、フォーム近傍にエラーメッセージ（例「タイトルを入力してください」）を表示し、画面遷移や停止をしない（AC-2）。
  - タスク一覧: 各行に「タイトル」「状態」を表示。状態は3値のセレクト（`未着手` / `対応中` / `完了`）で、変更すると即時に該当タスクを更新し一覧表示へ反映（AC-3）。
  - 空状態表示: 一覧が0件のとき「タスクがありません」等のメッセージ行を表示（AC-6）。
- API（ベースURL `/api`、Content-Type: `application/json`）:
  - `GET /api/tasks` → `200` `{ tasks: Task[] }`（全件返却、`created_at` 昇順）
  - `POST /api/tasks` 入力 `{ title: string }` → 成功 `201` `{ task: Task }` / `title` が空文字・欠落 `400` `{ error: string }`
  - `PATCH /api/tasks/:id` 入力 `{ status: "not_started" | "in_progress" | "done" }` → 成功 `200` `{ task: Task }` / 許可外 `status`・型不正 `400` `{ error: string }` / 該当 `id` なし `404` `{ error: string }`
- データ構造（SQLite `tasks` テーブル、PBI-001 で使う列）:
  - `id` INTEGER PRIMARY KEY AUTOINCREMENT
  - `title` TEXT NOT NULL
  - `status` TEXT NOT NULL DEFAULT 'not_started' CHECK (status IN ('not_started','in_progress','done'))
  - `created_at` TEXT NOT NULL（ISO8601）
  - `updated_at` TEXT NOT NULL（ISO8601）
  - ※ `due_date`（PBI-002）・`assignee`（PBI-003）列は後続PBIで追加する
- `Task` 型（API 応答の1要素）: `{ id: number, title: string, status: "not_started"|"in_progress"|"done", created_at: string, updated_at: string }`
- status 正規値と表示ラベルの対応:
  - `not_started` = 未着手 / `in_progress` = 対応中 / `done` = 完了

## 検証方法
- ローカルで API サーバと SvelteKit を起動する。
- 画面からタイトルを入力し登録 → 一覧に表示されることを確認（AC-1）。
- タイトル空で登録 → エラー表示・アプリ継続を確認（AC-2）。
- 状態を各値に変更 → 一覧反映を確認（AC-3）、再読み込みで保持を確認（AC-4）。
- `curl` で不正 status を PATCH → 400 を確認（AC-5）。
- 全タスク削除相当の空DBで一覧 → 空表示を確認（AC-6）。
- API の正常系・異常系の自動テストを `npm test` で実行し全通過を確認。
