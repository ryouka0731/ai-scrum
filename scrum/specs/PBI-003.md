# 仕様書: PBI-003 （担当者によるタスクの絞り込み）

- 作成日: 2026-08-14 / 更新日: 2026-08-14

## なぜ
チームリーダーが特定メンバーの担当タスクだけを取り出して進捗を確認できるよう、タスクに担当者を設定し、担当者で一覧を絞り込みたい。人単位の状況把握を容易にする。

## スコープ（やること）
- タスクへの担当者設定
- 担当者を指定した一覧の絞り込み
- 絞り込み解除による全タスク再表示
- 絞り込み結果0件時の明示

## Non-goals（やらないこと）
- 担当者マスタ管理（ユーザー登録・一覧・権限）— 担当者は自由入力の文字列として扱う
- 複数担当者（複数割当）や、担当者の複数選択フィルタ
- 担当者別の集計・件数表示（PBI-004 の領域）
- 認証・ログインユーザーに基づく自動絞り込み

## インターフェース / データ
- 画面:
  - 登録フォーム / タスク行に担当者入力欄を追加
  - 担当者による絞り込み操作（担当者選択 or 入力）と解除操作
  - 絞り込み中の状態表示、0件時のメッセージ
- API:
  - `POST /api/tasks` 入力に `assignee?: string`（省略可）を追加
  - `PATCH /api/tasks/:id` 入力に `assignee?: string | null`（設定・解除）を追加
  - `GET /api/tasks?assignee=<担当者>` → 指定担当者のタスクのみ返却（未指定時は全件）
- データ構造（`tasks` テーブルへの追加列）:
  - `assignee` TEXT NULL（担当者名の文字列、未設定は NULL）
- 絞り込み仕様: SQL の `WHERE assignee = ?`（パラメータ化クエリ）。他パラメータ（PBI-002 の sort）と併用可能。

## 検証方法
- 複数担当者のタスクを登録し、`GET /api/tasks?assignee=山田` で該当のみ返ることを確認（AC-2）。
- 画面で担当者を設定・保存し、再取得で保持を確認（AC-1）。
- 絞り込み解除で全件表示を確認（AC-3）。
- 存在しない担当者で絞り込み → 0件表示を確認（AC-4）。
- 絞り込み中の視覚表示を確認（AC-5）。
- 絞り込みが DB クエリ（WHERE）で行われることをコードレビューで確認（6-2）。

## 依存・リスク
- 依存: PBI-001（tasks テーブル・一覧・登録・更新の基盤）。PBI-002 とは独立に実装可能（併用は sort/filter パラメータ共存で対応）。
- リスク: 担当者が自由入力のため表記ゆれ（「山田」「山田太郎」）で絞り込み漏れが起きる → PoC では完全一致で割り切り、Non-goals に担当者マスタ化を明記。
